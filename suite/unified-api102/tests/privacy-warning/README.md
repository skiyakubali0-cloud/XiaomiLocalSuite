Run `python3 suite/unified-api102/tests/privacy-warning/run.py` from the workspace base (JDK 17+ and Android SDK 36).

The runner compiles the untouched production hooks and supplied Reflect against the actual API102 JAR and Android JAR. It executes registered Hooker instances with host Android/OEM fixtures, using the real API102 Chain interface. No legacy API, compatibility shim, native hook, adb, or device is used. All temporary output stays under this test directory and is removed on exit.

Only compiled host copies redirect mounted marker/framework/DEX paths. The two framework and APK pins are checked against the exact original constants, then replaced in those host copies with synthetic fixture hashes so actual Reflect.hashFile checks can run. The original Warning DEX and original package-private Payload SHA256 are used unchanged. Tests need the existing disaster/build/warning.dex and main's copied Payload.java.

Coverage includes ROM/marker/hash rejection, all named privacy endpoints and an overload, direct constructor registration, constructor exception identity, optional initialization failure, nested true/false/null restoration, original endpoint exceptions, per-thread isolation, root-only permission bypass within XiaoAI endpoints, nonassistant/cross-user/system UID rejection, missing XiaoAI package, local/input permission policy, Warning process restrictions, DEX prepend order, failed-verification retry, and repeated-load prevention.

Privacy installation tests inject failure at every one of 15 fixture registration positions in each of hook/builder/intercept, plus the final installation log. They execute each interceptor before commit and after rollback, asserting exact original result/exception identity, original execution once (including constructors), unchanged context/service/ThreadLocal, and reverse rollback of every returned handle. A rollback-error case verifies cleanup continues and preserves the original installation exception. Twelve class variants each omit one required method to prove installation rejects missing gates and rolls back. Retained failed-group callbacks are executed again after successful retry to prove they cannot become active with the new group. The activation flag is shared by the whole attempt and published only after installation completes; successful repeated calls do not duplicate hooks.

These tests exercise Java control flow and security conditions. They do not prove ART constructor hook execution, system-server callback timing, SELinux/reflection access, or native DexPathList class resolution. Warning must run from onPackageLoaded with getDefaultClassLoader before target classes resolve; Privacy must run from onSystemServerStarting before service construction. Neither component supports replay after hot reload: injected DEX elements/class definitions cannot be undone, and Privacy's captured context/UID assumes the original service/package lifecycle.
