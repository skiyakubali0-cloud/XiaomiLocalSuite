# 原电话与短信的禁用与恢复

此功能属于电脑源码工具 **0.7.1 prerelease**（`tool-v0.7.1`），不在历史 0.7.0 下载包中。公开下载仅含源码和教程，不是手机 ZIP，也不含原厂 APK/固件、SDK、第三方依赖或签名密钥。需要用当前源码重新构建统一 API102 APK、配套 `.build-evidence.json` 及 parent ZIP，两者一起更新；APK 须沿用现有插件的同一长期签名密钥，只更新 APK 不会补齐 Root 管理脚本。构建步骤见 [FULL_RECIPE.md](FULL_RECIPE.md)。目标仍是小米15 Ultra `xuanyuan`、EEA `OS4.0.0.6.XOAEUXM`、Android 17/API37。

## 使用

1. 用当前源码和同一长期签名密钥重建 API102 APK 与证据，再生成包含 `phone` 的配套 parent ZIP；选择电话会自动补齐 `market` 商店依赖，钱包无需选入。
2. 用户自行更新配套 APK/parent，并重新安装电话子组件；**旧电话子模块即使 versionCode/版本号相同，也须重装并手动重启**。禁用前会把已安装的 `restore-stock.sh`、`uninstall.sh` 摘要与本包 payload 比对，旧脚本会被拒绝。电话若需等待商店先重启，按部署日志完成续装，再手动重启使电话挂载生效。
3. 在统一插件 App 首页打开「原电话与短信 · 禁用 / 恢复」。
4. 点击「打开系统默认应用设置」，分别把小米电话和小米短信设为默认应用。
5. 返回后检查状态，按需点击「禁用原 Google 电话」或「禁用原 Google 短信」，确认后执行。两个应用分别管理，不随刷入、重启或应用预设自动禁用。

Google 电话 `com.google.android.dialer` 与 Google 短信 `com.google.android.apps.messaging` 独立管理。禁用只对机主用户 0 执行 `pm disable-user --user 0`，不卸载或清除应用数据，不修改电话底层、通话界面、联系人/短信数据服务、全局 XMSF 或 LSPosed 配置。需要换回时点击对应的「恢复」按钮，再到系统设置中选择默认应用；恢复按钮本身只重新启用原应用。

## 检查与恢复

禁用前重新核对 Root、精确系统、套件完整性、电话模块版本和生效状态、小米替代应用的锁定 APK 摘要、启用状态及默认角色。电话还核对通话界面。已安装电话组件的恢复与卸载脚本必须匹配本包；旧组件即使版本号相同也需重新安装并重启。模块更新待重启、组件未打包或任务正在执行时不允许禁用。原应用缺失时不代为下载安装。

操作使用与安装/恢复相同的控制器锁；禁用后核对实际状态与默认应用。失败时尝试重新启用原应用，并保留未确认恢复的标记。恢复原应用不要求小米电话模块仍然启用，但仍需匹配的系统、可用的 Root 和完整套件。

套件记录自己禁用的原应用。整项恢复电话组件时，先仅重新启用套件标记为自己禁用的原应用，再停用电话模块及恢复默认角色；重新启用失败则停止该恢复流程。独立卸载也持有同一个任务锁，直到默认角色与应用恢复流程结束；遇到已有任务就停止，不抢占锁。没有套件标记的外部禁用状态保持不变。

新源码的构建和主机模拟验证不等于手机行为验证；当前修改未安装到手机，也没有进行实际通话或短信收发测试。更新 APK 必须沿用原签名密钥，不能用临时测试签名覆盖现有插件。
